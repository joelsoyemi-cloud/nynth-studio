# NYNTH World build plan and Codex prompts

## Current foundation
Next.js App Router, React, strict TypeScript and plain CSS tokens. Motion provides accessible animation primitives. The landing page is a foundation preview, NOT the completed migration. `/reference/index.html` and `/reference/admin.html` contain the approved static designs. Current reference controls store demo data only. Preserve the original repository and deployment.

## Prompt 1 — React journal migration
Read AGENTS.md and this plan. Implement phase 1 only. Inspect docs/reference/index.html, story.html and stories.html and their assets. Rebuild the approved white editorial journal in reusable React components: header, campaign hero, Our Stories, Behind the Pieces, community, founder content and footer. Create /stories and /stories/[slug], with typed seed data, category filters and working navigation. Preserve copy, correct image subjects/proportions, layout alignment and Newman's priority; do not invent biography or publish filler as fact. Full story images must be uncropped and aligned with title/body. Keep product/shop links to the original store. Include loading, empty and not-found states as relevant. Keep real article text server rendered and metadata per story. Do not embed the old HTML or copy its imperative JS. Do not build a backend yet. Validate lint, types, production build and desktop/mobile layout; report changed files and remaining gaps. Commit phase 1.

## Prompt 2 — Motion system
Read AGENTS.md and inspect the completed phase 1. Implement a coherent animation system using Motion for React, preserving approved design. Build reusable DecryptedText, Reveal, StaggerGroup, ImageReveal and ReadingProgress components. Use decrypted text on one short brand phrase, word/line reveal for selected editorial headlines, subtle card stagger, image-mask entrances, button/underline microinteractions, restrained route entrances and scroll reading progress. Keep images sharp on hover. At most one desktop-only cinematic scroll sequence may use GSAP + @gsap/react and ScrollTrigger if justified; lazy load it, scope selectors, revert on teardown and use a static mobile fallback. No competing engines on the same properties. Native scrolling by default; no extra scroll library. Honour reduced motion for ALL custom effects, avoid hydration mismatches, preserve semantic text for screen readers and no-JS users, clean timers/observers, keep controls immediately usable. Check keyboard, mobile, reduced motion, layout shifts and console errors. Run lint/typecheck/build and document what was actually tested. Commit phase 2.

## Prompt 3 — React studio demo
Read AGENTS.md. Migrate the approved docs/reference/admin.html, admin-v2.css and admin.js to a React /studio area matching its layout. Build overview, stories, story editor/preview, media, homepage order, submissions, store products, store connection and brand settings. Use a typed versioned demo repository with localStorage persistence, hydration-safe reads, schema validation, storage error handling and a reset confirmation. Clearly label demo status. Link journal and studio. Implement product-to-story draft creation and duplicate prevention. Do not pretend demo Published changes the public site or that refresh fetches real products. Use short functional drawer/list transitions, focus handling and escape to close. No fake authentication. Verify create/edit/save/reload, image validation, product linking, reset and responsive keyboard use. Commit phase 3.

## Prompt 4 — Real publishing architecture, then implementation
Read AGENTS.md. First audit the completed journal and studio, and propose a concrete backend plan with schemas for profiles/roles, stories/statuses, media, categories, homepage ordering, submissions and linked store products. Joel will select/connect the backend before credentials or migrations are needed. Cover Newman/admin/editor/contributor permissions, server-side authorization, draft privacy, publish/unpublish, input validation, storage policies, audit trail and article cache revalidation. The public journal and studio must share one source of truth. Do not ship localStorage as a CMS or rely on a hidden dashboard link. Add integration tests for unauthorized publishing, unpublished content isolation and publish-to-public flow. Implement only after the backend/account decisions are supplied; report any real access blockers.

## Prompt 5 — Store integration
Confirm the actual main-store platform and available API with its developer; the client called it WooCommerce but it is not verified. Never scrape logged-in store/admin pages. Build a server-only product adapter, starting with a documented read-only feed. Use canonical IDs and idempotent upserts. Sync images/name/price/availability when supplied, but never overwrite authored stories or publish automatically. If webhooks exist, verify signatures, deduplicate events, retry safely and add periodic reconciliation. Keep checkout/orders on the main store. Expose sync status, last successful update and actionable failures. Test invalid signatures, duplicate events, product removal and outages. No browser-exposed API secrets.

## Release
Separate GitHub repo: proposed joelsoyemi-cloud/nynth-studio. Separate Vercel project nynth-studio in joelsoyemi-clouds-projects. Production branch main; framework Next.js; default build/output detection; no SPA rewrite. Connect Git integration for preview deployments. Verify project/team/commit before release. No backend secrets are needed for phases 1–3.
